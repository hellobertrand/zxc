# libzxc.org

Source of the ZXC website, [libzxc.org](https://libzxc.org). The site is static
HTML generated by `build.mjs`:

- the landing page comes from `src/index.html` and `src/data/benchmarks.json`;
- every documentation page is generated from this repository (`docs/*.md`,
  `src/cli/zxc.1.md`, `CHANGELOG`), so the site never drifts from the code;
- the version shown everywhere is read from `include/zxc_constants.h`;
- the Doxygen reference (`/docs/doxygen/`) is generated from `docs/Doxyfile.in`,
  `include/` and `src/lib/` when `doxygen` is installed (required in CI).

The only npm dependency is [`marked`](https://www.npmjs.com/package/marked),
pinned in `package-lock.json`. The design is deliberately plain, in the style of
GNU project pages and Texinfo manuals: no framework and no inline JavaScript.

Pages make three kinds of third-party request:

- Noto Sans and Noto Sans Mono from Google Fonts (`layout()` in `build.mjs`),
  with system fonts as fallback;
- the GitHub API, for the star count (`src/assets/site.js`, cached for an hour
  in `localStorage`; the build also fetches it once to render it statically);
- the Repology packaging badge on the landing page (`src/index.html`).

## Local preview

```sh
cd site
npm ci
npm run dev            # builds ./dist from ../docs and serves it on http://localhost:8080
```

This previews the documentation of your working copy. CI builds from the latest
release tag instead; `REPO_ROOT=/path/to/checkout npm run build` does the same
locally.

## Deployment

`.github/workflows/pages.yml` builds the site and deploys `dist/` to Cloudflare
as a Worker serving static assets (no branch, no committed HTML):

| Event | What happens |
| --- | --- |
| Release published (`v*` tag) | Rebuild with the docs of the newest release (that one, unless it is an older maintenance release) and deploy |
| Push to `main` touching `site/**` | Rebuild with the docs of the newest release and deploy |
| Pull request touching `site/**` | Build only, as a check |
| Manual run | Deploy (from `main` only); `docs_ref` builds the docs from any ref, e.g. `main` |

The documentation is taken from the **newest release tag**, not from `main`, so
the published API reference and format specification always match what users
can install.

The site's settings are in this directory: `wrangler.jsonc` (domain, 404 page)
and `src/_headers` (response headers, cache lifetimes).

## Updating content

| To change | Edit |
| --- | --- |
| Benchmark figure, tables, levels table | `site/src/data/benchmarks.json` |
| Landing page copy | `site/src/index.html` |
| Docs pages and their order | the Markdown in `docs/`, and the `DOCS` list in `build.mjs` |
| Header, footer, `<head>` | `header()`, `footer()`, `layout()` in `build.mjs` |
| Styles | `site/src/assets/site.css` (dark theme included) |
| Social preview image | `tools/og.html`, then `python3 tools/render-images.py` |
